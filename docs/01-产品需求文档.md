# IPTools 产品需求文档（PRD）

> 版本：v0.1  
> 状态：初稿  
> 日期：2026-11-18

## 1. 背景

用户当前需要在多个工具和网页之间手工操作：

1. 直接运行 CFST，从本机测试 Cloudflare IPv4/IPv6 边缘 IP 的延迟、丢包和下载速度；
2. 测试延迟、丢包和下载速度；
3. 从 CSV 中挑选较优 IP；
4. 登录海外 VPS 上的 3X-UI；
5. 找到已有客户端并复制节点链接；
6. 将节点链接和优选 IP 粘贴到 goodip 页面；
7. 生成订阅并导入 V2rayN、Clash/Mihomo、Shadowrocket 或 Surge。

流程重复、容易复制错误，并且缺少任务历史、订阅更新和安全的凭据管理。

## 2. 产品目标

### 2.1 核心目标

将“节点获取、IP 测速、地址筛选、节点转换、订阅发布”整合为一个可观察、可重复、可恢复的桌面工作流。

### 2.2 成功指标

- 用户无需打开 CFST 终端；
- 完整流程中无需打开 goodip 网页；
- 接入 3X-UI 后，无需打开面板复制节点；
- 常用方案可在 3 次点击内开始执行；
- 测速完成后，可在 1 分钟内获得订阅；
- 已导入客户端的订阅 URL可复用，不必每次重新导入；
- 敏感信息不出现在普通日志和界面截图中。

### 2.3 非目标

首版不计划：

- 追求与 CFST 每个高级参数完全兼容；应用采用满足本产品链路的原生测速内核；
- 替代 3X-UI 管理全部入站和用户；
- 直接修改代理客户端内部配置文件；
- 提供公共机场或节点售卖能力；
- 支持复杂的多租户商业运营；
- 支持 macOS、Linux、Android 和 iOS 桌面端。

## 3. 目标用户

### 3.1 主要用户

- 拥有海外 VPS；
- 已部署 3X-UI/Xray；
- 使用 Cloudflare CDN；
- 需要定期寻找更优连接地址；
- 使用 Windows 管理节点；
- 使用 V2rayN、Clash/Mihomo、Shadowrocket 或 Surge。

### 3.2 用户痛点

- 多次复制粘贴，容易遗漏或贴错；
- CFST 参数难记；
- 无法直观看到任务阶段和失败原因；
- 不清楚哪些 IP 已用于哪个订阅；
- 每次生成新订阅后可能需要重新导入；
- 节点密钥和面板凭据存在泄露风险。

## 4. 核心使用场景

### 场景 A：首次生成订阅

1. 用户配置 3X-UI 连接，或粘贴原始节点；
2. 导入 IP/CIDR 并选择测速方案；
3. 开始测速；
4. 软件自动选取 Top N，也允许手工调整；
5. 用户预览生成节点；
6. 发布订阅；
7. 复制 URL 或二维码导入客户端。

### 场景 B：更新已有订阅

1. 用户打开历史订阅；
2. 点击“重新测速并更新”；
3. 软件复用原节点与方案；
4. 生成新版本并展示差异；
5. 用户确认发布；
6. 原订阅 URL 保持不变，客户端下次刷新时获得新节点。

### 场景 C：3X-UI 暂时不可用

1. 连接测试失败；
2. 软件说明失败原因；
3. 用户选择历史节点快照或手工粘贴节点；
4. 继续完成测速和订阅生成。

## 5. 信息架构

建议一级导航：

1. **概览**：快速开始、连接状态、最近任务和订阅；
2. **IP 测速**：目标、参数、进度和结果；
3. **节点来源**：3X-UI 面板、入站、客户端和手工节点；
4. **订阅**：预览、发布、URL、二维码和版本；
5. **历史**：测速任务、生成记录和失败记录；
6. **设置**：核心程序、服务地址、凭据、安全和日志。

## 6. 功能需求

### F-01 Cloudflare IP 优选配置（P0）

- 普通流程不要求填写 VPS、域名或测速 URL；
- 延迟阶段默认测试“本机 → Cloudflare 边缘 IP”，与 CFST 默认 TCPing 模型一致；
- 下载阶段留空 URL 时使用 CFST 默认地址 `https://cf.xiu2.xyz/url`；该公共地址可用性不作承诺；
- 用户仅在测试其他 CDN、自建测速文件或需要验证特定 Host/SNI 链路时填写自定义 URL；
- 提供 IPv4/IPv6 简单切换；
- 默认使用内置 Cloudflare 官方候选网段；
- 候选 IP/CIDR 只在高级设置中展示和修改；
- 主界面明确说明候选 IP 是 Cloudflare 边缘入口；
- 支持保存常用优选方案。

**验收：**普通流程无需接触 CIDR 或填写 URL，直接完成 TCPing、筛选和默认下载测速；填写自定义 URL 后，原生引擎以候选 IP 建连并保留该 URL 的 Host/TLS SNI；无效 CIDR 不进入测速。

### F-02 原生测速参数配置（P0）

- 提供快速、均衡、严格、自定义预设；
- 覆盖线程、次数、端口、URL、TCPing/HTTPing；
- 覆盖延迟上下限、丢包率、最低速度、下载数量和时间；
- 支持地区码；
- 高级参数默认折叠；
- 原生引擎不拼接 shell 命令；高级区显示最终生效参数，敏感 URL 只在当前任务中使用。

### F-03 测速任务（P0）

- 启动应用内置 Rust 测速任务；
- 每次任务使用独立任务 ID，并以 SQLite 状态记录隔离；
- 实时展示阶段、日志、已完成数量和耗时；
- 支持取消；
- 捕获网络超时、响应错误和解析错误；
- 禁止两个测速任务同时运行或写入同一任务状态。

### F-04 结果管理（P0）

- 表格展示 IP、发送、接收、丢包、延迟、速度、地区；
- 支持排序、筛选和搜索；
- 自动选择 Top N；
- 支持手工勾选、排除和复制；
- 支持导出 CSV；
- 保存任务参数和完整结果。

### F-05 节点导入（P0）

- 支持 VMess、VLESS、Trojan 分享 URI；
- 支持一行一个；
- 支持 Base64 原始订阅；
- 解析后展示协议、名称、地址、端口、TLS、传输类型；
- UUID、密码、订阅 ID 默认脱敏；
- 不支持的节点明确标记，不静默丢弃。

### F-06 goodip 发布（P0）

- 把节点、优选地址、名称前缀和 Host/SNI 策略提交到生成接口；
- 展示原始节点数、优选地址数和输出节点数；
- 展示前 20 个生成节点预览；
- 展示 Raw、Clash、Surge 和自动识别 URL；
- 提供复制和二维码；
- 服务失败时允许导出本地结果。
- 首次发送前明确说明节点内容将提交至第三方服务；
- 提供“不再提示”选项，但可在设置中恢复；
- 用户可以完全禁用第三方发布，只在本地生成节点文件。
- 发布服务地址可配置，默认值为 `https://goodip.supconit.cc.cd`；
- 生成接口路径可配置，默认值为 `/api/generate`；
- 提供“测试连接”，验证 HTTPS、接口可达性和响应合约；
- 支持可选 Bearer API Key，为未来兼容服务预留；
- 地址变更仅适用于兼容 goodip 请求/响应合约的服务，不承诺任意订阅服务可直接替换。

### F-07 3X-UI 连接（P1）

- 配置带自定义根路径的面板 URL；
- API Token 优先；
- 支持测试连接和能力探测；
- 获取入站和客户端；
- 过滤启用/禁用、协议和备注；
- 获取官方分享链接，或根据配置构造；
- 提供手工导入降级入口。

### F-08 节点组合预览（P1）

- 支持笛卡尔组合与每节点 Top N；
- 优选地址可覆盖端口；
- 默认保留原 Host/SNI；
- 展示转换前后差异；
- 显示最终节点数量；
- 对数量过大、重复名称、无 SNI 等情况警告。

### F-09 固定订阅更新（P2，需要自有服务）

- 创建订阅后获得稳定 URL；
- 更新只增加内容版本，不改变 URL；
- 发布前预览差异；
- 发布失败时保持上一版本；
- 支持撤销和轮换访问令牌。

当前 goodip 不由用户控制且没有后端源码，本功能不能建立在现有第三方接口必然支持的假设上。实现前需要自建订阅发布服务，或获得一个具有完整管理 API 的可信服务。

### F-10 历史与诊断（P1）

- 保存测速任务、节点来源、发布记录和错误；
- 支持按状态、时间和订阅筛选；
- 支持从历史任务重新运行；
- 导出脱敏诊断包；
- 日志区分普通、调试和敏感字段。

## 7. 关键交互规则

- “一键生成”不是无确认发布：首次使用必须经过预览；
- 默认只替换连接地址，不替换 Host/SNI；
- 自动选择的 Top N 必须可手工修改；
- 取消测速后不得自动发布旧的或不完整的结果；
- 3X-UI 连接失败时不清除原有凭据；
- 发布按钮必须显示将更新的订阅名称和节点数量；
- 完整 URI 仅在主动复制或查看时短暂显示；
- 所有不可逆操作需要明确对象，不使用笼统的“确定”。

## 8. 状态模型

一次完整任务状态：

```text
草稿
  → 正在准备
  → 延迟测试
  → 下载测试
  → 等待选择
  → 生成预览
  → 正在发布
  → 已完成
```

任意执行状态可进入：

- 已取消；
- 已失败；
- 等待用户处理。

失败后保留已产生的日志和可用结果，但不得自动进入下一阶段。

## 9. 非功能需求

### 性能

- 应用冷启动目标不超过 3 秒；
- 10,000 行结果表格仍可流畅滚动；
- UI 线程不得执行网络、文件解析或进程等待；
- 大文本和 CSV 使用流式或后台解析。

### 可靠性

- 应用崩溃后能识别未完成任务；
- 发布采用先创建新版本、成功后切换的方式；
- 数据库写入使用事务；
- 任务输出目录不可复用。

### 可用性

- MVP 使用低干扰的浅色桌面主题：暖灰画布、白色工作区、石墨文字，仅用低饱和靛蓝表示选择和焦点；
- 后续可增加深色主题，但不得牺牲信息层级和对比度；
- 关键状态不只依赖颜色；
- 中文为首发语言；
- 支持键盘操作、可复制错误详情和高 DPI。

### 安全

- 使用系统凭据库保存 Token；
- TLS 证书验证默认开启；
- 日志、历史列表和崩溃报告脱敏；
- 不把完整节点链接写入普通配置文件；
- 自动更新包需要签名和完整性校验。

## 10. MVP 范围

MVP 包含 F-01～F-06，但 F-06 必须同时提供第三方发布和本地导出两条路径：

```text
配置并运行原生测速
→ 选择优选 IP
→ 粘贴原始节点
→ 调用 goodip
→ 获得并复制订阅
```

3X-UI 自动连接、固定订阅更新和完整历史属于下一阶段，但 MVP 的数据模型和界面必须为其预留扩展点。

## 11. MVP 验收场景

1. 用户选择 IPv4 或 IPv6 后直接测速；自定义测速 URL 和候选网段默认隐藏；
2. 用户启动测速，能看到日志并可取消；
3. 测速成功后展示 CSV 全部字段；
4. 软件按规则选出 Top 10，用户可改为 5 个；
5. 用户粘贴 VMess/VLESS/Trojan 节点，软件显示解析结果；
6. 软件调用 goodip 并显示各格式订阅；
7. 用户可以复制 URL 或查看二维码；
8. 任何失败均显示可理解的原因，且不会泄露节点密钥；
9. 重新打开软件能看到上一任务的非敏感摘要；
10. 测速过程不依赖或修改任何外部 CFST 目录。

## 12. 待决定问题

- 正式产品名与图标；
- WPF 还是 Tauri；
- 自有订阅发布服务何时建设；
- 第三方 goodip 在新安装中默认关闭；用户阅读风险提示并显式开启后才能发布；
- 自定义发布服务是否需要额外 Header 或不同认证方式；
- 固定订阅 URL 的数据保留周期；
- 首版需要适配的具体客户端版本；
- 3X-UI 当前服务器版本及 API Token 能力。
