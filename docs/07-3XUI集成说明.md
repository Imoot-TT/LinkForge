# 3X-UI 集成说明

> 日期：2026-11-18  
> 实现版本：LinkForge 0.1.0

## 采用的官方能力

当前 3X-UI 官方文档说明，`/panel/api/*` 同时支持登录会话 Cookie 和 Bearer API Token。IPTools 同时支持软件内账号登录与 API Token：账号登录适合不想单独配置 Token 的用户，Token 适合长期自动化调用。

官方当前版本提供：

- `GET /panel/api/inbounds/allLinks`：通过订阅引擎返回所有入站及客户端的分享链接；
- `GET /panel/api/inbounds/list/slim`：返回精简的入站和客户端摘要，不是当前版本的分享链接接口；
- `GET /panel/api/inbounds/list`：返回完整入站配置；
- `GET /panel/api/clients/list`：返回客户端及其关联的入站 ID；
- `GET /panel/api/clients/links/{email}`：返回指定客户端在所有关联入站下的分享链接；
- 分享链接可能包含 VMess、VLESS、Trojan 等协议，并且包含客户端凭据，应按密码处理。

## 当前实现

1. 用户在设置页填写含自定义根路径的面板 URL；
2. 用户可选择账号登录，或填写 API Token；
3. 账号登录按面板前端的实际流程建立匿名会话、获取 `/csrf-token`，继承刷新后的会话 Cookie，并以 `application/x-www-form-urlencoded` 提交 `username`、`password` 和可选 `twoFactorCode`；
4. 用户明确勾选保存时，用户名和密码以一个系统凭据项写入 Windows Credential Manager；前端只可查询“是否已保存”和用户名，不能读取密码；
5. 启动时 Rust 后端可直接读取保存的凭据自动登录；启用 2FA 时仍只需输入本次验证码；登录成功后只提取 `3x-ui` HttpOnly 会话 Cookie，保存在 Rust 进程内存中；
6. “选择 3X-UI 客户端”先调用 `clients/list`，默认优先选中名为 `mt` 的客户端，再以 URL 安全编码后的 email 调用 `clients/links/{email}`；
7. 客户端关联的每个 VMess/VLESS/Trojan 节点均独立展示，可多选后写入原始节点区；例如 `mt` 下的 `vmess-ws-tls-mt:443` 可单独选择；
8. “读取全部节点”仍保留为兼容入口，调用 `inbounds/allLinks`；
9. 所有面板接口只允许 HTTPS，使用登录 Cookie 或 Bearer Token 发起只读请求，响应上限为 2 MiB；
10. 链接进入界面前先生成不含 UUID/密码的预览；用户名、密码、2FA、Cookie 和节点密钥不写入 localStorage、SQLite 或普通日志；
11. `allLinks` 返回 404/405 时自动尝试 `list/slim` 兼容响应，并接受字符串数组、`obj.links` 及对象中的 `link`/`url` 字段。

## 兼容限制

- 较旧 3X-UI 版本可能没有 `allLinks` 或 API Token；软件会尝试兼容响应，仍失败时保留手工粘贴入口；
- 当前客户端选择基于 3X-UI v3.11 的一等客户端 API；旧版本缺少 `clients/list` 或 `clients/links/{email}` 时仍可读取全部节点或手工粘贴；
- 软件内 Cookie 只存在于当前应用进程；若用户未选择保存账号，关闭软件后需要重新登录；
- 用户也可选择只在当前会话使用 Token，或将其保存到 Windows Credential Manager；已保存的 Token 不会回填到界面；
- 软件不会读取 Chrome、Edge 等浏览器的 Cookie。浏览器 Cookie 是 HttpOnly 且浏览器配置与 Tauri WebView/原生 HTTP 客户端隔离，读取它既不稳定也会扩大隐私权限；
- 软件不调用新增、更新、删除或重置流量等写接口。

## 当前实测证据

- 用户提供的面板根路径可匿名返回登录页；
- `GET /tsVOm7wtiLvoSwnVZS/csrf-token` 可返回 `success: true` 和 CSRF 字符串；
- 面板前端登录脚本确认 `POST /login` 使用表单编码，客户端接口使用 `X-CSRF-Token` 和 `credentials: same-origin`；
- 未使用真实账号提交登录，因此账号密码正确性和登录后的只读节点字段仍需用户在本机验证。

## 后续开发

1. 用用户面板的只读实测验证 v3.11 返回字段和 `mt` 下 `vmess-ws-tls-mt` 的显示名称；
2. 增加带本地 HTTP 夹具的 Bearer、Cookie、404 降级和响应上限集成测试；
3. 对分享链接重复项和不支持协议给出汇总提示。

Windows 凭据存储通过 [keyring-rs](https://docs.rs/keyring/latest/keyring/v1/index.html) 的 Windows 原生后端实现；该后端使用 Windows Credential Manager。
