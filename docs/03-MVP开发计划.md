# IPTools MVP 开发计划

> 版本：v0.1  
> 日期：2026-11-18

## 1. MVP 目标

交付一个 Windows 桌面程序，完成：

```text
输入自有 VPS/CDN 测速 URL → 原生 Rust 测速 → 选择优选 IP
→ 粘贴原始节点 → 发布 → 获得订阅 URL
```

MVP 不以功能数量为目标，要求主链路可靠、错误可理解、敏感数据不泄露。

## 2. 阶段与交付物

### 阶段 0：技术 Spike

**目的：**消除框架和外部接口的不确定性。

任务：

- 验证 Rust 原生候选生成、TCP/HTTPing、取消和下载测速；
- 验证通过 DNS 覆盖连接候选 IP 时仍保留原域名 TLS/SNI；
- 验证 CSV 导出及 SQLite 历史恢复；
- 仅用虚构节点调用 goodip 接口，验证协议和响应；
- 验证返回的 Raw、Clash、Surge URL；
- 验证本地生成/导出路径在 goodip 不可用时仍能工作；
- 验证 Tauri 的导航、表格、日志、中文输入、高 DPI 和 Windows 打包。

交付物：

- 原生测速引擎验证记录；
- `spikes/goodip-client`；
- 可运行的 Tauri UI 样例；
- 技术选型 ADR；
- 风险清单更新。

完成标准：

- 从测试输入到订阅响应能够自动闭环；
- 确定正式 UI 技术栈；
- 无阻塞级未知风险。

### 阶段 1：应用骨架

任务：

- 建立项目结构和 CI；
- 导航、主题、窗口状态；
- 统一错误和日志；
- SQLite 迁移；
- 设置和目录管理；
- Secret Store 抽象；
- 测试基线。

完成标准：

- 应用可安装、启动和升级数据库；
- 页面切换稳定；
- 日志不泄露测试凭据。

### 阶段 2：测速闭环

任务：

- VPS/CDN 测速 URL 与 IPv4/IPv6 快速选择；
- 内置 Cloudflare 候选网段，高级模式才显示编辑器；
- 参数预设；
- 原生测速请求构造；
- 独立任务 ID 与 SQLite 状态；
- 异步任务、阶段日志、取消和异常中断识别；
- CSV 导出；
- 结果表格和 Top N；
- 历史摘要。

完成标准：

- 不读取、启动或修改外部 CFST 目录；
- 成功、失败、取消均有确定状态；
- 10,000 行结果可操作；
- Top N 结果可复制和导出。

### 阶段 3：节点与订阅闭环

任务：

- VMess/VLESS/Trojan 导入；
- Base64 订阅识别；
- 节点脱敏预览；
- 优选 IP 与节点组合；
- goodip 客户端；
- 可配置发布服务 Base URL、生成路径、超时与可选 API Key；
- 不含真实节点的连接与合约测试；
- 本地订阅/节点导出器；
- 订阅结果、复制和二维码；
- 发布失败的本地导出兜底。

完成标准：

- 三种协议的标准样例往返不丢字段；
- 默认保留 Host/SNI；
- 能获得并展示各格式订阅；
- 请求、日志和历史无明文凭据。

### 阶段 4：MVP 稳定化

任务：

- 完整端到端测试；
- 无网络、服务超时、CSV 损坏等故障测试；
- 安装包、卸载和升级；
- 诊断包；
- UI 一致性、高 DPI 和可访问性；
- 用户文档。

完成标准：

- PRD 中 10 个 MVP 验收场景全部通过；
- 不存在 P0/P1 缺陷；
- 可在干净的 Windows 10/11 环境安装运行；
- 发布包带版本、哈希，正式版应签名。

### 阶段 5：3X-UI 集成（MVP 后）

任务：

- API Token 与凭据库；
- 能力探测；
- 入站和客户端列表；
- 分享链接读取或构造；
- 连接诊断；
- 手工入口降级。

### 阶段 6：固定订阅更新（MVP 后）

任务：

- 建设或接入可控的订阅管理服务；
- 自有服务 v1 管理 API；
- 创建、更新、撤销和轮换；
- 版本历史和差异；
- 发布事务和回滚；
- 定时测速仅生成草稿，用户确认后发布。

## 3. 建议代码仓库结构

框架确定前使用概念结构：

```text
IPTools/
  docs/
  src/
    App/
    Application/
    Domain/
    Infrastructure/
      SpeedTest/
      Nodes/
      ThreeXui/
      GoodIp/
      Persistence/
      Secrets/
  tests/
    Unit/
    Integration/
    Fixtures/
  spikes/
  packaging/
```

若选择 Tauri，可将 UI 与 Rust 命令层分开；若选择 WPF，则将视图、ViewModel 与核心项目分开。Domain 和接口含义保持一致。

## 4. 测试夹具

开发前应准备且不得提交真实凭据：

- 小型 IPv4 列表；
- 小型 IPv6 列表；
- 混合有效/无效 CIDR；
- 成功、空结果、损坏表头的 CSV；
- 脱敏 VMess、VLESS、Trojan；
- 带 IPv6、WS、gRPC、TLS、Reality 等边界样例；
- 3X-UI 多版本 mock 响应；
- goodip 成功和错误响应。

所有测试 UUID、域名、Token 均使用明确的虚构值。

## 5. 发布门槛

每个版本发布前：

- 自动化测试通过；
- 依赖漏洞扫描通过；
- 日志脱敏测试通过；
- 安装、升级、卸载测试通过；
- 确认发布包不依赖外部 CFST；
- 外部服务健康检查通过；
- 更新变更和已知限制；
- 构建产物生成 SHA-256；
- 正式发布使用代码签名。

## 6. 风险优先级

| 优先级 | 风险 | 验证阶段 |
|---|---|---|
| P0 | 原生测速无法可靠取消或保留 TLS/SNI | 阶段 0～2 |
| P0 | goodip 接口缺少稳定合约 | 阶段 0 |
| P0 | 敏感节点进入日志/数据库 | 阶段 1～3 |
| P1 | UI 技术栈无法满足大表格和审美 | 阶段 0 |
| P1 | 3X-UI 版本不兼容 | 阶段 5 |
| P1 | 固定订阅无法事务更新 | 阶段 6 |
| P2 | 代理客户端格式差异 | 阶段 3～4 |

## 7. 下一步工作

当前阶段 0～3 已有可运行实现，下一步集中完成稳定化：

1. 使用虚构节点验证 goodip 真实响应字段；
2. 增加 3X-UI Bearer、404 降级和响应上限的本地 HTTP 集成夹具；
3. 增加取消、超时、无网络和长结果故障测试；
4. 在干净 Windows 10/11 环境执行安装、升级和卸载验证；
5. 获得正式代码签名证书后签署发布包。
