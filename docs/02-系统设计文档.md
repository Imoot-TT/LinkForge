# IPTools 系统设计文档

> 版本：v0.1  
> 状态：架构初稿  
> 日期：2026-11-18

## 1. 设计原则

- UI 不直接拼接命令、解析协议或访问数据库；
- 外部系统均通过适配器隔离；
- 任务可取消、可追踪、可诊断；
- 敏感数据与普通业务数据分离；
- 首版可以复用第三方 goodip，但不让业务层依赖其具体格式，并提供本地发布器；
- 3X-UI、订阅服务和测速核心均可替换。

## 2. 系统上下文

```text
用户
 │
 ▼
IPTools 桌面端
 ├── 内置 Rust 测速内核
 ├── 本地 SQLite
 ├── Windows Credential Manager
 ├── 远程 3X-UI API
 └── 远程 goodip API / 订阅服务
                    │
                    ▼
       V2rayN / Clash / Shadowrocket / Surge
```

## 3. 逻辑分层

### Presentation

- 页面、对话框、导航；
- 表单校验反馈；
- 任务状态和结果展示；
- 不保存凭据，不直接调用外部服务。

### Application

- `RunSpeedTestUseCase`；
- `ImportNodesUseCase`；
- `Load3XuiClientsUseCase`；
- `BuildSubscriptionPreviewUseCase`；
- `PublishSubscriptionUseCase`；
- 编排状态、取消和错误映射。

### Domain

- IP/CIDR、测速方案、测试任务；
- 节点、端点、组合策略；
- 订阅、版本和发布状态；
- 不依赖 CFST、3X-UI、WPF 或 Tauri。

### Infrastructure

- Rust 原生异步测速引擎；
- CSV 解析器；
- 3X-UI HTTP 客户端；
- goodip HTTP 客户端；
- SQLite 仓储；
- 凭据库；
- 日志与系统集成。

## 4. 主要模块

| 模块 | 职责 |
|---|---|
| Speed Profile | 保存 IP 版本、测速参数、可选自定义 URL 与候选网段 |
| Target Parser | 在后台解析、规范化、去重内置或高级设置中的 IP/CIDR |
| Native Speed Engine | 候选抽样、TCP/HTTP 延迟、丢包、下载测速与取消 |
| Result Exporter | 将结构化结果导出为 CSV |
| Ranking Engine | 根据延迟、丢包、速度和地区选择 Top N |
| Node Parser | 解析 VMess/VLESS/Trojan 与 Base64 订阅 |
| 3X-UI Adapter | 认证、能力探测、入站/客户端/链接读取 |
| Node Transformer | 结构化替换连接地址和端口，保留 Host/SNI |
| Subscription Publisher | 抽象发布能力；支持第三方 goodip、本地导出及未来自有服务 |
| History Store | 保存任务、结果摘要、订阅和版本 |
| Secret Store | 保存 API Token 等敏感凭据 |
| Diagnostics | 结构化日志、脱敏和诊断包 |

## 5. 领域模型

### SpeedProfile

```text
id, name, mode(TCP/HTTP), concurrency, attempts,
downloadCount, downloadSeconds, port, url,
latencyMin, latencyMax, packetLossMax, speedMin,
coloFilters, disableDownload, testAllIpv4
```

`url` 是可选覆盖项。为空时，TCPing 直接连接候选 Cloudflare IP，下载测速使用 CFST 默认地址 `https://cf.xiu2.xyz/url`；填写后通过 DNS 覆盖连接候选 IP，同时保留 URL 原域名的 Host 与 TLS SNI。

### TargetSet

```text
id, name, sourceType, rawContent, normalizedCount,
invalidCount, createdAt, updatedAt
```

`rawContent` 可能包含用户数据，持久化策略需允许关闭。

### TestRun

```text
id, profileSnapshot, targetSnapshotHash, coreVersion,
status, stage, startedAt, completedAt, exitCode,
workDirectory, resultCount, errorCode, errorSummary
```

### TestResult

```text
runId, address, sent, received, packetLoss,
averageLatencyMs, downloadSpeedMBps, colo,
rank, selected, excluded
```

### SourceNode

```text
id, sourceId, protocol, displayName, server, port,
transport, tlsMode, host, sni, fingerprint,
secretReference, enabled, parseWarnings
```

敏感字段不直接进入普通表；可以短期保存在加密存储或仅驻留内存。

### PreferredEndpoint

```text
address, optionalPort, label, sourceResultId
```

### Subscription

```text
id, name, publisher, remoteId, status,
createdAt, updatedAt, currentVersionId
```

### SubscriptionVersion

```text
id, subscriptionId, testRunId, sourceSnapshotHash,
endpointSnapshot, nodeCount, createdAt, publishStatus
```

### PanelConnection

```text
id, name, baseUrl, authMode, credentialReference,
allowInvalidCertificate=false, detectedVersion,
capabilities, lastCheckedAt
```

## 6. 本地数据表建议

- `speed_profiles`
- `target_sets`
- `test_runs`
- `test_results`
- `panel_connections`
- `node_sources`
- `subscriptions`
- `subscription_versions`
- `app_settings`

数据库不保存：

- 明文 3X-UI Token；
- 面板密码；
- 完整节点 URI；
- 完整订阅访问令牌；
- 可直接还原 UUID/密码的普通日志。

## 7. 原生测速引擎

### 7.1 默认流程

1. 从每个 IPv4 `/24` 随机抽取一个候选；IPv6 每个前缀抽取一个候选；
2. 以 TCPing 测试本机到候选 IP 的延迟与丢包；
3. 按延迟上下限和丢包率过滤并排序；
4. 使用 CFST 默认下载地址，按低延迟顺序对指定数量候选测速；
5. 按下载速度降序、延迟升序输出结果。

该流程不启动、不读取也不修改用户磁盘上的 `cfst.exe`。

### 7.2 自定义 URL 与 HTTPing

- 自定义 URL 仅用于其他 CDN、自建测速文件或特定域名链路验证；
- HTTP 客户端将 URL 域名解析覆盖为当前候选 IP，但 TLS 校验与 SNI 仍使用原域名；
- 测速客户端强制直连，不继承系统代理，避免得到代理节点延迟；
- 3X-UI 和 goodip 等管理请求可继承 Windows 系统代理。

### 7.3 进度与取消

- 阶段包含准备、延迟测试、下载测速和完成；
- 延迟阶段报告已完成/总数，下载阶段报告队列进度；
- 每次任务使用 UUID，并将状态、参数和结果写入 SQLite；
- 网络等待以短周期检查取消标志，卡住的下载也能及时取消。

### 7.4 CSV 导出

- CSV 直接由结构化结果生成，不解析外部 CFST 文件；
- 使用 UTF-8 BOM 兼容 Excel 中文显示；
- 导出 IP、发送、接收、丢包率、延迟、速度和地区码。

## 8. 3X-UI 适配器

### 8.1 URL 处理

用户配置的是包含自定义根路径的 Base URL。所有 API 路径基于该 URL 安全拼接，不假设站点根目录。

### 8.2 认证优先级

1. Bearer API Token；
2. 会话登录 + CSRF + 可选 OTP；
3. 手工节点/订阅导入。

### 8.3 能力探测

连接时记录：

- 版本；
- API Token 支持；
- 入站列表接口；
- 完整入站接口；
- 链接生成接口；
- 订阅服务状态；
- 协议集合。

业务层只读取能力标志，不判断版本字符串。

## 9. 节点解析与转换

### 9.1 解析规则

- VMess：解析 Base64 JSON；
- VLESS/Trojan：解析 URI authority、query 和 fragment；
- 未知 query 参数必须保留；
- 解码失败返回行号、协议猜测和错误原因；
- 不在日志输出完整原文。

### 9.2 转换规则

默认：

- `server = preferredEndpoint.address`；
- 若端点有端口，则替换 `port`；
- 保持 `host`；
- 保持 `sni`；
- 保持路径、TLS、Flow、指纹、ALPN 和凭据；
- 重新生成名称；
- IPv6 使用标准 URI 方括号。

### 9.3 组合上限

默认输出不超过 200 个节点。超过时必须提示并要求减少原节点或 Top N，具体上限可配置。

## 10. 订阅发布器与 goodip API 合约

### 10.1 发布器接口

业务层依赖统一的 `SubscriptionPublisher`，至少提供：

- `ThirdPartyGoodIpPublisher`：调用现有第三方接口；
- `LocalExportPublisher`：在本地生成/保存节点或订阅内容；
- `ManagedPublisher`：未来对接自有固定订阅服务。

第三方发布器不得承担历史记录、固定 URL、撤销和版本回滚等产品承诺。

### 10.2 可配置服务设置

```text
publisherType: goodip-compatible
baseUrl: https://goodip.supconit.cc.cd
generatePath: /api/generate
authMode: none | bearer
credentialReference: optional
timeoutSeconds: 30
enabled: true
```

约束：

- `baseUrl` 与 `generatePath` 分开存储和规范化拼接；
- 默认只允许 HTTPS；开发环境使用 HTTP 时必须显式开启；
- API Key 保存到系统凭据库，配置中只保存引用；
- “测试连接”使用虚构或空探测数据，不上传真实节点；
- 测试需要验证 HTTP 状态、JSON 结构及必要字段；
- 用户更换 URL 不会自动改变协议解析方式；不兼容的服务需要新的 Publisher 实现。

### 10.3 已观察到的第三方接口

已观察到的创建请求：

```http
POST /api/generate
Content-Type: application/json
```

```json
{
  "nodeLinks": "...",
  "preferredIps": "...",
  "namePrefix": "CF",
  "keepOriginalHost": true
}
```

桌面端内部不直接使用网页响应对象，而映射为：

```text
PublishResult
  remoteId?
  autoUrl
  rawUrl
  clashUrl
  surgeUrl
  inputNodeCount
  endpointCount
  outputNodeCount
  preview[]
  warnings[]
```

未来自有服务的建议接口：

```text
POST   /api/v1/subscriptions
PUT    /api/v1/subscriptions/{id}
GET    /api/v1/subscriptions/{id}
DELETE /api/v1/subscriptions/{id}
POST   /api/v1/subscriptions/{id}/rotate-token
GET    /health
```

更新接口应实现固定 URL 和内容版本化。由于当前 goodip 不由用户控制且没有后端源码，这些接口不能要求第三方提供，需要另行建设自有服务。

## 12. 安全设计

### 12.1 数据分级

- 普通：界面设置、非敏感测速参数；
- 内部：IP 结果、面板地址、任务历史；
- 敏感：API Token、UUID、密码、完整节点和订阅 URL。

### 12.2 凭据

- Windows Credential Manager 或等价系统密钥库；
- 数据库只保存凭据引用；
- 凭据读取只发生在调用适配器的短生命周期内；
- UI 不提供永久“显示 Token”；
- 复制敏感内容后可选定时清空剪贴板。

### 12.3 网络

- HTTPS 默认强制；
- 证书异常应显示指纹和风险，不允许全局忽略；
- HTTP 客户端设置超时、大小限制和重试策略；
- 发布请求不得自动无限重试，防止创建重复订阅。
- 向第三方 goodip 发送完整节点前必须获得用户明确确认；
- 设置中可完全禁用第三方发布器；
- 第三方接口响应不得被视为永久可用或可恢复的数据备份。

### 12.4 日志脱敏

脱敏内容包括：

- Authorization 和 Cookie；
- UUID、密码和订阅 ID；
- URI user-info；
- URL query 中的 token；
- 请求与响应正文中的节点内容。

## 13. 测试策略

### 单元测试

- IP/CIDR 校验；
- 候选生成与测速参数校验；
- CSV 多语言表头；
- VMess/VLESS/Trojan 解析与往返；
- IPv6 与端口处理；
- Host/SNI 保留；
- 日志脱敏。

### 集成测试

- 使用本地测试服务模拟测速成功、失败、超时和取消；
- 使用 mock server 模拟 3X-UI 多版本响应；
- 使用 mock server 模拟 goodip 超时、错误和成功；
- SQLite 崩溃恢复和事务。

### 真实环境测试

- Windows 10/11；
- 高 DPI 与中文路径；
- 系统代理开启/关闭；
- IPv4/IPv6 混合输入；
- 实际 3X-UI 版本；
- V2rayN、Clash/Mihomo、Shadowrocket、Surge 导入。

## 14. 可观测性

- 每个任务和发布操作生成 correlation ID；
- 日志采用结构化字段；
- 记录阶段耗时而非敏感请求正文；
- 诊断包包含版本、哈希、系统信息、错误和脱敏日志；
- 默认不上传遥测，未来如增加必须显式征得同意。

## 15. 待验证技术点

- 默认公共下载测速地址的可用性；
- 取消、超时与系统代理开启时的直连行为；
