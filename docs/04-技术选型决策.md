# IPTools 技术选型决策

> 状态：已决定（Rust + Tauri）  
> 候选：.NET + WPF / Rust + Tauri  
> 日期：2026-11-18

## 1. 决策目标

选择能同时满足以下要求的桌面技术：

- Windows 10/11 稳定运行；
- 现代深色视觉，接近现有 goodip 页面审美；
- 稳定管理 CFST 子进程；
- 大结果表格、日志和任务状态流畅；
- 安全访问系统凭据；
- 安装、更新和诊断可维护；
- 为未来跨平台或重写测速内核保留空间。

## 2. 候选 A：.NET + WPF

### 优势

- Windows 桌面生态成熟；
- 进程、文件、HTTP、SQLite 和凭据接入直接；
- MVVM 和数据绑定适合管理工具；
- DataGrid、无障碍、高 DPI 和中文输入成熟；
- 部署和调试链路稳定。

### 劣势

- 只支持 Windows；
- 默认外观传统，达到现代 Web 视觉需要完整主题系统；
- XAML 样式和复杂动画维护成本不低；
- 如果未来采用 Rust 测速核心，会形成双语言架构。

### 适用条件

- 明确长期只做 Windows；
- 更重视系统集成和开发稳定性；
- UI 采用 Fluent/现代工具风，而不是高度 Web 化的动效界面。

## 3. 候选 B：Rust + Tauri

### 优势

- HTML/CSS 更容易还原现有 goodip 深色页面；
- Rust 适合进程管理，并为未来自研测速核心铺路；
- 相比 Electron 通常体积和资源占用更低；
- 具备跨平台潜力；
- 前端生态适合图表、虚拟表格和二维码。

### 劣势

- 同时维护 Rust 与 TypeScript/前端框架；
- 依赖系统 WebView2；
- 前后端命令边界、安全权限和错误传递更复杂；
- Windows 凭据、托盘、协议唤起和安装更新要逐项验证；
- WebView 行为和平台版本需要兼容测试。

### 适用条件

- 视觉需要高度接近现代 Web 产品；
- 未来可能跨平台；
- 团队能维护 Rust 和前端两套技术；
- 计划将测速、节点解析等核心逐步迁移到 Rust。

## 4. 初步评分

评分 1～5，需用 Spike 修正：

| 维度 | 权重 | WPF | Tauri |
|---|---:|---:|---:|
| Windows 系统集成 | 20% | 5 | 4 |
| 视觉自由度 | 20% | 3.5 | 5 |
| 开发与调试稳定性 | 15% | 5 | 3.5 |
| 大表格/管理界面 | 10% | 4.5 | 4.5 |
| 资源占用 | 10% | 4 | 4.5 |
| 未来跨平台 | 10% | 1 | 4.5 |
| Rust 核心演进 | 10% | 2.5 | 5 |
| 安装与维护 | 5% | 4.5 | 3.5 |

当时的评分显示 Tauri 在视觉迭代、Rust 核心演进和未来跨平台方面占优；正式 Spike 后已用 Tauri 完成 Windows 可运行 MVP、原生 Rust 测速内核、凭据保存和安装包构建，因此不再保留 WPF 作为当前实现路线。

## 5. 必须完成的对比 Spike

两个候选实现同一个页面：

- 左侧导航；
- 顶部状态栏；
- 三张统计卡片；
- 10,000 行虚拟化 IP 表格；
- 实时追加日志；
- 进度条和取消按钮；
- 深色/浅色切换；
- 模拟保存和读取凭据；
- 调用一个长时间子进程并取消。

统一测试：

- 冷启动时间；
- 空闲与运行内存；
- 表格滚动帧率和筛选延迟；
- 日志追加时 UI 响应；
- 125%、150%、200% 缩放；
- 中文输入；
- Windows 10/11；
- 安装包大小；
- 开发代码量与错误处理复杂度。

## 6. 决策规则

优先选择 Tauri，如果：

- 视觉样例明显更符合预期；
- 大表格和日志性能达到标准；
- WebView2、凭据库和安装更新验证通过；
- 确定未来要自研 Rust 测速核心或跨平台。

优先选择 WPF，如果：

- 产品长期仅支持 Windows；
- Tauri 在系统集成、安装或 WebView 兼容上出现明显风险；
- WPF 样例通过主题设计已满足审美；
- 更重视尽快稳定交付。

## 7. 最终决策

最终选择 **Rust + Tauri**。当前证据包括：Tauri Windows WebView2 MVP 可启动、Rust 测速核心和网络请求已内置、Windows Credential Manager 已接入、NSIS/MSI 均可生成；领域模型、原生测速接口、3X-UI 接口和 goodip 合约保持分层，便于独立演进。正式发布前仍需完成真实面板验证、第三方发布服务验证和代码签名。
